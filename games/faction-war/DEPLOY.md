# 초대제 웹 테스트 서버 배포

현재 공개 링크와 호스팅 계정은 없습니다. 아래는 Render Docker Web Service 기준 수동 배포 절차입니다. 다른 Docker 호스팅도 사용할 수 있습니다. 영구 디스크를 지원하는 상품과 그 비용은 호스팅 화면에서 확인하고 결정해야 합니다. 이 문서는 배포 완료나 보안 인증을 의미하지 않습니다.

1. 이 폴더를 별도 비공개 GitHub 저장소에 올립니다. `data/` 및 실제 비밀 설정은 올리지 않습니다. Dockerfile, auth.js, server.js, public/를 포함합니다.
2. Render 계정을 만들고 해당 저장소를 연결해 Docker Web Service를 만듭니다. 아직 외부 사용자를 초대하지 않습니다.
3. 인스턴스 수는 1로 설정합니다. 영구 디스크를 `/app/data`에 연결합니다. 임시 파일 시스템만 사용하는 배포는 캐릭터 저장 용도로 사용할 수 없습니다.
4. 호스팅이 할당한 HTTPS 주소를 확인하고 다음 환경 변수를 설정합니다.

| 변수 | 값/설명 |
|---|---|
| NODE_ENV | production |
| HOST | 0.0.0.0 |
| APP_ORIGIN | 실제 HTTPS 원점. 경로와 끝의 `/` 없이 입력 |
| DATA_DIR | /app/data |
| INVITE_CODE | 비밀 변수. 비밀번호 관리자로 생성한 32자 이상 무작위 값 권장 |
| ADMIN_USERNAME | 초기 운영자 계정명. 영문·숫자·밑줄 3~24자 |
| ADMIN_PASSWORD | 초기 운영자 비밀번호. 12~128자, 충분히 긴 고유 비밀번호 사용 |

PORT는 호스팅이 주입한 값을 그대로 사용합니다. 비밀 값을 채팅이나 저장소에 붙이지 않습니다. 첫 운영자 계정 생성 후 ADMIN_PASSWORD 설정을 삭제할 수 있습니다. 운영자 계정이 이미 있으면 초기 비밀번호 설정으로 계정 비밀번호를 덮어쓰지 않습니다.

5. 환경 설정 후 다시 배포합니다. production 모드는 HTTPS 원점·초대 코드·최초 관리자 설정이 빠지면 시작하지 않습니다. 브라우저에서 접속해 운영자 계정으로 로그인합니다.
6. 일반 계정은 초대 코드로 생성합니다. 두 기기로 서로 다른 계정에 접속해 공유 월드와 채팅을 확인합니다. 같은 계정의 새 로그인은 기존 세션을 종료합니다.
7. 운영 관리에서 테스트 계정을 차단하고 즉시 연결 종료 및 재로그인 거부를 확인합니다. 해제 후 캐릭터가 유지되는지 확인합니다.
8. 서버를 정상 종료한 상태에서 `world.json`과 `accounts.json`을 한 쌍으로 별도 백업합니다. 두 파일 모두 민감한 운영 데이터입니다. 별도 테스트 저장 공간에 복원해 계정·캐릭터·차단 상태가 일치하는지 확인합니다. 실행 중 파일을 따로 복사하면 일관성이 깨질 수 있습니다.
9. 호스팅의 HTTPS 강제, 실제 클라이언트 IP 기반 제한, SSE 버퍼링 해제 및 연결 제한을 확인합니다. 현재 앱은 전달된 X-Forwarded-For를 신뢰하지 않습니다. 대규모 공개 모집 전에 운영 방어·부하 시험을 진행합니다.

## 계정 운영 한계

- 이메일 확인, 비밀번호 재설정·변경, MFA 및 관리자 복구 UI는 아직 없습니다. 비밀번호를 잊으면 UI로 복구할 수 없으므로 초대제 테스트로 제한합니다.
- 로그인과 등록은 IP당 합산 분당 10회로 제한합니다. 프록시 뒤에서는 이 한도를 공유할 수 있습니다.
- scrypt 비밀번호 해시 및 무작위 salt를 사용하며 동시에 최대 4건만 해시합니다. 계정 로그인 세션은 7일이며 로그아웃·재로그인·차단 시 폐기합니다.
- 초대 코드가 유출되면 가입을 막기 위해 코드 교체와 서버 재시작이 필요합니다. 코드 교체가 기존 계정을 자동 차단하지는 않습니다.
- 기존 익명 캐릭터는 삭제하지 않지만 새 계정에 자동 귀속하지 않습니다. 다른 사용자의 소유권을 확인할 수 없는 상태에서 임의로 연결하지 않습니다.
- 운영 기록은 최근 500건만 저장합니다. 별도 감사 로그 보관과 외부 자동 백업은 미구현입니다.
