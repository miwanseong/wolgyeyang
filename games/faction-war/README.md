# 진영전쟁 · 변경의 서약

중세 판타지 협동 RPG·경영 게임의 첫 플레이 프로토타입입니다. 완성 게임이나 MMO 서버가 아닙니다. 외부 패키지 없이 Node.js 22 이상으로 실행합니다. 검증 환경은 Node.js 24입니다.

```sh
cd /workspace/wolgyeyang-games
npm start
```

기본 포트는 3100이며 `PORT`로 변경합니다. 같은 서버의 주소로 접속하는 플레이어들이 월드를 공유합니다. 기본 서버는 127.0.0.1에만 바인딩합니다. 외부 바인딩은 HOST 설정과 초대 코드가 있어야 가능합니다. 외부 접속에는 배포 환경의 포트 공개 및 HTTPS 구성이 필요합니다. 클라우드 외부 접속은 아직 검증하지 않았습니다.

- WASD/방향키: 연속 이동, 대각 이동 지원
- E: 손에 든 도구 사용. 농사·낚시는 해당 도구를 장착해야 한다.
- SPACE: 방향별 근접 공격, 기술/회피는 설정의 키 배치를 따른다.
- I: 통합 가방·분류·사용·설정, C: 장비, K: 기술, M: 지도, H: 지정한 빠른 사용
- Enter: 채팅. 채팅 패널에서 전체/파티 전환과 파티 관리
- 최신 마을·보스·연출·무료 패스 변경은 [PLAY_UPDATE.md](PLAY_UPDATE.md), 수익 모델은 [MONETIZATION.md](MONETIZATION.md) 참고

## 멀티플레이와 저장

SSE로 상태를 공유하며 행동은 서버가 검증합니다. 한 프로세스가 하나의 월드를 운영합니다. 초대 코드로 계정을 만들고 로그인합니다. 같은 계정은 다른 브라우저/기기에서도 같은 캐릭터를 복원합니다. HttpOnly·SameSite=Strict 쿠키 세션은 7일간 유효하며 새 로그인은 기존 세션을 폐기합니다. 비밀번호는 scrypt로 해시하고 세션 토큰은 SHA-256 해시로만 저장합니다. 계정 복구는 미구현입니다. `data/world.json`에 5초마다 원자적 교체 방식으로 저장하며 정상 종료 시에도 저장합니다. `DATA_DIR`로 별도 저장 위치를 지정할 수 있습니다. 공개 운영 전에 인증, TLS, 프록시 제한, 백업, 관리 도구와 부하 검증이 필요합니다. world.json과 accounts.json은 함께 보관하고 공개하지 마세요. 운영자 계정으로 접속하면 계정 목록·차단·해제·최근 운영 기록을 확인할 수 있습니다.

```sh
npm test
```

실제 서버에 두 클라이언트를 연결해 공유 월드, 거리·이동 검증, 작물 성장·수확, 조리·판매, 종료 후 캐릭터 복원을 확인합니다. 테스트는 작물 성장과 이동 간격 때문에 약 40초 걸립니다. 보안 회귀 테스트도 포함합니다.

## 세계관과 아트 범위

진영전쟁은 사용자 원작입니다. 브론즈 100 = 실버 1, 실버 1000 = 골드 1인 체계 중 현재 프로토타입은 브론즈만 사용합니다. 개척지, 기본 화염술, 마수 및 장비 수치는 검증용 임시 콘텐츠이며 정사로 확정하지 않습니다. 현재 픽셀 도형은 임시 그래픽입니다. 한글은 기기 내 명조 서체를 사용하고 외부 웹 폰트는 불러오지 않습니다.

블랙 디 크라이스(묵혈검), 트와일라잇(과거 용병명 조커, 고유 마법 카드 뽑기), 마스아기아, 벨라 니그라, 익시크, 이세리아 및 다른 원작 캐릭터의 최종 디자인·서사는 이번 버전에 구현하지 않았습니다. 연애, 종족 선택, 진영전, 건축, 거래, 고유결계와 장기 서비스 기반도 후속 범위입니다.

## 비공개 테스트 배포 기준

아직 공개 배포하지 않았습니다. 먼저 초대제 테스트 서버로 운영합니다. 인터넷 운영 시 다음 환경 설정이 필요합니다.

- NODE_ENV=production
- HOST=0.0.0.0
- APP_ORIGIN: 실제 HTTPS 사이트 원점 (예: https://game.example.com, 끝에 / 없음)
- INVITE_CODE: 최소 16자 이상의 무작위 초대 코드. 호스팅의 비밀 변수로 등록하며 저장소에 커밋하지 않습니다.
- DATA_DIR: 비휘발성 디스크 경로. Docker에서는 /app/data 볼륨을 연결합니다.

HTTPS 종료 프록시 뒤에 서버를 두고 직접 서버 포트를 인터넷에 노출하지 않습니다. 전달받은 X-Forwarded-For는 현재 신뢰하지 않으므로 IP 제한은 프록시 주소를 공유할 수 있습니다. 프록시 측에서 실제 클라이언트 IP 기준 접속·요청량 제한을 별도로 적용해야 합니다. 여러 인스턴스를 실행하는 구조가 아니므로 단일 인스턴스로 운영합니다. SSE 버퍼링을 끄고 자동 재연결을 지원해야 합니다.

초대 코드는 계정별 차단과 별개입니다. 익명 캐릭터 대량 생성, 광범위한 서비스 거부 공격, 다중 계정 파밍, 쿠키 삭제 후 복구, 게임 이용자의 운영 분쟁은 완전히 해결되지 않았습니다. 신규 생성 제한은 IP당 분당 10회와 월드당 100 캐릭터이며, 운영자 차단·해제 UI가 있으며 캐릭터 삭제는 지원하지 않습니다. 공개 서비스 전에는 계정 복구 및 MFA, 엣지 방어, 복원 시험을 거친 백업, 감사 로그와 부하 시험이 필요합니다.

쿠키 인증, Origin/Fetch Metadata 검사, JSON 크기 제한, API 요청량 제한, 서버 판정 이동 간격, SSE 접속 수 및 송신 버퍼 제한, CSP 등 기본 응답 헤더를 적용했습니다. HTTPS 환경에서만 Secure 쿠키와 HSTS를 활성화합니다. 구형 localStorage 인증 토큰은 새 클라이언트에서 제거하며 자동 이전하지 않습니다.

Docker 설정은 제공하지만 이 환경에서 이미지를 빌드·실행 검증하지는 않았습니다.


## 계정과 운영자

브라우저 UI는 계정 등록·로그인을 사용합니다. 로컬 개발은 초대 코드 없이 가입할 수 있습니다. 첫 운영자는 ADMIN_USERNAME / ADMIN_PASSWORD 환경 변수로 생성합니다. production 모드에서는 운영자 초기 설정이 필수이며, 익명 접속은 허용하지 않습니다. 개발 테스트용 구형 익명 API는 루프백 개발 모드에만 남겨 두었습니다. 이전 캐릭터는 보존하지만 새 계정에 자동 연결하지 않습니다.

호스팅 설정, 비용 확인 지점, 비밀 변수, 배포 후 검증 절차와 제한은 [DEPLOY.md](DEPLOY.md)를 참고하세요. 계정 테스트는 로그인 회전, 권한 우회 거부, 연결 중 차단, 재시작 후 차단 보존, 차단 해제, 로그아웃을 검증합니다. 브라우저의 실제 화면 자동화와 외부 호스팅 검증은 아직 하지 않았습니다.

## 탐험·직업 업데이트

- 기존 계정은 로그인 후 캐릭터 이름과 검사·마법사·사냥꾼·장인 중 기본 직업 하나를 선택합니다. 선택은 서버에 저장되며 변경할 수 없습니다.
- 검사: 체력 130, 근접 피해 +5. 마법사: 체력 90, 화염술 즉시 습득, 주문 피해 +8. 사냥꾼: 기본 공격 사거리 4, 피해 +2. 장인: 체력 110, 수확 +1, 빵 판매 +15 브론즈.
- 마을 훈련관(12,8) 가까이에서 R로 의뢰 수락. 수락 이후 마수 3회 처치, 광석 4개, 경험치 30을 모아 보고하면 기본 직업별 전직합니다. 광석과 경험치를 소모하고 체력 +20 및 피해 +8을 얻습니다.
- 숲(50,12)의 흔적을 조사하고 경험치 20으로 그림자방랑자 히든 전직이 가능합니다. 일반 전직과 히든 전직은 한 캐릭터에서 중복되지 않습니다.
- 마을·속삭이는 숲·잿빛 성채는 각 64×48 타일입니다. 마을(59,24) ↔ 숲(3,24), 숲(32,4) ↔ 성채(32,44)의 표지석에서 R 또는 수첩 버튼으로 이동합니다. 각 지역은 문 없는 경계 통과가 아닌 명시적 연결 지역입니다.
- 늑대·해골·직업 캐릭터·집·침엽수는 생성된 8비트 도트 스프라이트 아틀라스를 사용합니다. 현재 단일 포즈이며 걷기·타격 애니메이션은 미구현입니다. 숲·성채의 적은 근처 온라인 플레이어를 추적합니다.
- 체력·직업·경험치는 좌상단 HUD, 현재 위치와 출구는 우상단 미니맵에 표시합니다. I로 배낭을 열어 소지품과 키 설정을 확인합니다. 키 설정은 브라우저 로컬 저장이며 중복 입력을 거부합니다. 이동 방향키도 사용할 수 있습니다.
- 시장/작업장은 하단 버튼으로 열며 거래·제작은 실제 시설 근처에서만 가능합니다. 나무 줄기와 집 본체는 이동을 막습니다. 집 내부와 건축, 완전한 지형 타일셋, 스트리밍 오픈월드는 후속 범위입니다.

이 업데이트의 직업·전직명·훈련관은 검증용 임시 설정입니다. 사용자가 제공한 원작 인물을 임의로 교사나 보스로 배치하지 않았습니다. 기존 캐릭터·농장·계정 저장은 보존하며 새 필드를 기본값으로 추가합니다. 무료 호스팅의 저장 초기화 가능성은 계속 적용됩니다.

## 화면·지형·조명 업데이트

- 플레이 중에는 게임 캔버스가 브라우저 뷰포트를 채웁니다. 우상단 전체화면 버튼은 브라우저 Fullscreen API를 사용합니다. 지원하지 않는 브라우저에서도 뷰포트 레이아웃은 유지됩니다. 수첩·채팅은 우상단 버튼으로 열고 기존 HUD와 I 인벤토리를 유지합니다.
- 실외 3개 지역은 각 192×144 타일입니다. 이전 64×48 대비 지역 면적이 9배이며 기존 지역 연결과 퀘스트 위치는 보존합니다. 도로, 강·다리, 주택 구역과 추가 마수 배치를 넣었습니다. 지붕·벽·바닥은 정면/직교 격자로 구성하며 대각선 집 스프라이트는 더 이상 사용하지 않습니다.
- 잡화점·대장간·여관·개척자 집·숲지기 오두막의 남쪽 문 근처에서 R로 실내에 들어갑니다. 남쪽 출입구에서 R로 돌아옵니다. 일부 확장 주택은 외관만 있으며 모든 건물에 실내가 있는 것은 아닙니다.
- layout.js의 동일한 벽·가구·수목 배치를 이동 충돌과 렌더링·조명에 사용합니다. 실내는 정면 책장·카운터·침대·식탁·벽난로·모루를 배치하고 바닥과 가구를 깊이 순서로 그립니다.
- 캐릭터의 횃불은 이동을 따라가며 켜고 끌 수 있습니다. 불빛은 작은 시간 변화로 흔들리고 광원 거리의 제곱에 따른 감쇠를 근사합니다. 실내 창은 차가운 외광, 촛불과 벽난로는 따뜻한 광원으로 구분합니다.
- 조명은 낮은 해상도 라이트맵에 벽·가구 차폐 다각형을 계산하고 곱셈 합성합니다. 목재·석재의 한 번짜리 확산 반사와 가까운 물 위 광원의 움직이는 반사 띠는 근사 효과입니다. 실제 레이트레이싱·다중 바운스 GI·3D 높이에 따른 정확한 반사·그림자·금속의 정밀 정반사는 구현하지 않았습니다.
- 동적 조명과 그림체를 함께 유지하기 위해 라이트맵은 픽셀 단위로 확대하고 밝기 단계를 제한합니다. 외신이나 마법이 없는 일반 생활 광원은 촛불·벽난로·창문을 기준으로 합니다.
- 브라우저 검사에서 전체화면 진입·해제, 뷰포트 채우기, 건물 출입, 횃불을 끌 때 렌더 밝기 감소, 벽 뒤 픽셀의 조도 감소를 확인합니다. 고부하·다수 광원 및 저사양 실제 기기 성능 시험은 후속 검증입니다.

## 아이템·인물 도감과 3D 반사

- 현재 구현된 소지품(씨앗·밀·빵·광석·브론즈)과 기본 직업 장비(검·지팡이·활·망치)에 새 도트 아이콘을 적용했습니다. 인벤토리·장비 슬롯·거래창과 도감에서 확인합니다.
- 묵혈검, 트와일라잇의 카드 뽑기, 이세리아의 영혼 기생 꽃은 설정을 참고한 **디자인 연구 시안**입니다. 일반 드롭/판매/장착 아이템으로 구현하지 않았습니다.
- 새 인물 초상은 사용자 피드백에 따라 이번 배포에서 제외했습니다. 원본 얼굴 도트의 방향만 확인됐으며 전신 얼굴 형태·목 길이는 추가 조정이 필요합니다. 원작 NPC를 임시 일반 캐릭터로 대체하지 않습니다.
- WebGL 사용 가능 시 Three.js 0.180.0 기반 2.5D 렌더러를 사용합니다. 직교 카메라, 도트 빌보드 캐릭터·소품, 실제 높이가 있는 건물·벽, PBR 재질, 그림자 맵을 결합합니다. 캐릭터 자체는 완전한 3D 모델이 아닙니다.
- 강과 실내의 젖은 부분은 Reflector의 가상 카메라로 장면을 실제 다시 렌더링합니다. 물결은 반사 좌표를 조금 흔듭니다. 금속은 저해상도 동적 큐브 환경맵과 거칠기·금속성으로 주변 빛과 장면을 반영합니다. 목재·석재에는 작은 범프 효과를 적용합니다.
- 물 반사는 알파와 색을 조정한 스타일화된 평면 반사입니다. 전역 레이트레이싱, 완전한 다중 바운스 GI, 완전한 수중 굴절·물리적 Fresnel 계산은 없습니다. 젖지 않은 목재와 돌을 거울처럼 만들지 않습니다.
- 원본 Three Reflector의 투영 처리를 직교 카메라에도 동작하도록 일반 역투영 방식으로 수정했습니다. 큐브맵 캡처 중 자기 환경맵을 읽는 피드백을 방지합니다. Third-party 고지와 MIT 라이선스는 public/vendor에 포함됩니다.
- 우상단 3D 버튼으로 2D 렌더러에 전환할 수 있으며 WebGL 생성 실패 시 2D로 폴백합니다. 모바일 실제 기기 성능은 추가 검증이 필요합니다.
- 서버가 승인한 공격에 맞춰 짧은 발광 궤적·입자·잔상을 표시합니다. 효과는 3D 반사 장면에도 포함됩니다. 참고 작품의 원본 스프라이트·애니메이션·이펙트를 복제하지 않았습니다. 다방향 걷기·공격 모션과 완성형 스킬 애니메이션은 후속 범위입니다.

브라우저 검증은 실제 WebGL 프레임·반사면 활성화, 반사 텍스처에서 캐릭터를 숨겼을 때 픽셀 변화, 아이템 아이콘 로딩, 기존 계정·조작 흐름을 검사합니다. 렌더러는 로컬 벤더 모듈만 사용하고 CDN 연결은 필요하지 않습니다.

최근 테스트 빌드는 [구현 범위와 남은 작업](CONTENT_STATUS.md)에 정리했습니다. 기본 키는 Shift 회피, F 누르기/놓기 마법 차징, I 인벤토리·키 설정, K 특성, M 지역 지도, B 노점·상단 거래소입니다. 화염술은 훈련관에게 먼저 배우세요. 효과음은 첫 클릭/키 입력 후 활성화되며 인벤토리에서 음량·화면 흔들림·흑백 효과 강도를 조절합니다.

장비창은 C, 걷기는 WASD, 달리기는 V를 누른 채 이동, 회피는 Shift입니다. K에서 직업 기술 습득·등급 투자·1/2/3 배치를 합니다. 기술 포인트와 특성 포인트는 별도입니다. 낚싯대는 제작하거나 시장에서 구한 뒤 다리·해안 가까이에서 R 상호작용으로 사용합니다. 도구와 장비 수리는 대장간에서, 부상 치료는 치료소에서 합니다. 세부 범위는 CONTENT_STATUS.md, 원작과 보충 설정은 WORLD_FOUNDATION.md, 초기 수치는 BALANCE.md를 참조하세요.

낚시 개편: 낚시 수첩에서 128종 도감·개체 보관함·낚싯대/찌/줄을 관리합니다. 물가에서 손 도구를 낚싯대로 선택하고 E → 입질에 SPACE → 누르기/놓기로 막대 조절 순서입니다. 물고기는 자랑·판매·손질·방생할 수 있습니다. E의 농사 기능도 괭이를 실제로 장착해야 동작합니다. 자세한 내용은 FISHING.md를 참조하세요.
