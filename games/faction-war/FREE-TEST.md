# 무료 테스트 링크 만들기

이 패키지는 Render의 Free Web Service를 대상으로 구성했습니다. render.yaml은 `plan: free`를 명시하고, 유료 디스크·데이터베이스·추가 서비스를 만들지 않습니다. 무료 플랜의 제공 여부·사용량 한도는 가입 및 생성 화면에서 확인해야 하며 유료 상품으로 자동 대체하지 않습니다. 현재 계정 연결이 없어 외부 배포는 아직 실행하지 않았습니다.

1. Render에 가입하고 GitHub를 연결합니다.
2. 이미 업로드된 저장소 miwanseong/wolgyeyang의 game/faction-war-free-test 브랜치를 선택할 수 있습니다. 해당 브랜치 루트의 render.yaml은 games/faction-war를 사용하도록 설정되어 있습니다. 별도 저장소를 사용할 경우 이 폴더 내용을 새 GitHub 저장소의 루트에 업로드합니다. 다운로드한 ZIP을 풀고 파일들을 올려야 합니다. ZIP 파일 자체만 올리면 배포되지 않습니다. `data/`, 비밀번호, 계정 저장 파일은 포함하지 않습니다.
3. Render에서 **New → Blueprint**로 저장소를 선택하고 브랜치를 game/faction-war-free-test로 지정합니다. `render.yaml`을 읽은 결과가 Free Web Service 하나이고 유료 리소스가 없는지 확인한 뒤 생성합니다. 무료 플랜을 제공하지 않으면 유료 플랜을 선택하지 말고 중단합니다.
4. 배포가 끝나면 Render가 표시하는 HTTPS 서비스 주소로 접속합니다. 앱은 플랫폼의 `RENDER_EXTERNAL_URL`을 사용하므로 주소를 소스 코드에 적을 필요가 없습니다.
5. 서비스의 환경 변수에서 자동 생성된 `ADMIN_PASSWORD`와 `INVITE_CODE`를 확인합니다. 운영자 계정명은 `operator`입니다. 비밀번호를 채팅에 보내지 마세요. 이 서비스는 초대제이며 일반 사용자는 초대 코드로 가입합니다.
6. 서로 다른 두 계정을 만들고 같은 링크에 접속해 이동·채팅·농사를 확인합니다. 관리자 화면에서 테스트 계정의 차단·해제를 확인합니다.

## 무료 테스트의 제약

- 계정·농장·아이템은 임시 디스크에 있습니다. 재배포나 인스턴스 교체, 휴면 복구 등에 따라 모두 초기화될 수 있습니다.
- 무료 서비스는 휴면 상태에서 처음 접속할 때 기동 대기가 생길 수 있습니다. 제공 업체의 현재 정책을 따릅니다.
- 테스트에서는 자동 생성된 초기 관리자 비밀번호를 환경 변수에 유지하세요. 임시 디스크가 초기화됐을 때 관리자를 재생성하는 데 필요합니다.
- 계정 복구·MFA·분산 서버·외부 백업·대규모 공격 방어는 아직 없습니다. 소수 초대제로만 테스트합니다.
- Docker 배포와 실제 Render 외부 연결은 아직 검증하지 않았습니다. 로컬 Node HTTP 통합 테스트와는 별개입니다.

지속 운영을 결정한 뒤 영구 저장 공간과 백업을 붙입니다. 이 단계에서는 유료 저장 공간이 필요하지 않습니다.
